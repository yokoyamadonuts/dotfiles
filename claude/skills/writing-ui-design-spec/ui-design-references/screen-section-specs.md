## セクション 0: 概要

各画面の冒頭に配置する概要ブロック。

### テンプレート

```markdown
### 概要

| 項目 | 内容 |
|---|---|
| **目的** | [この画面がユーザーに提供する価値] |
| **主要CTA** | [1つの主要アクション] |
| **表示条件** | [この画面にアクセスする条件] |
| **デザイン原則** | [最重要原則: Warmth / Clarity / Growth / Trust / Flow 等] |
```

## セクション 1: ワイヤーフレーム（ASCIIアート）

### ルール

- **幅**: モバイルファースト（375px相当）で作成
- **表現**: ボックス文字（`┌─┐│└─┘`）でレイアウト構造を表現
- **粒度**: 個々のテキストではなく、コンポーネント単位で表現
- **ステップ画面**: 全ステップ分のワイヤーフレームを作成（タブやウィザード含む）
- **注釈**: 右側にコメント（`← 説明`）を追加可

### テンプレート

```
┌─────────────────────────────┐
│  StatusBar                   │
├─────────────────────────────┤
│  [Header / NavBar]           │
├─────────────────────────────┤
│                              │
│  [メインコンテンツ領域]        │
│                              │
│  ┌───────────────────────┐  │
│  │ ComponentName          │  │ ← DS参照: セクションX.Y
│  │ [内容の概要]            │  │
│  └───────────────────────┘  │
│                              │
│  ┌───────────────────────┐  │
│  │ [CTA Button]           │  │ ← Primary / Full-width
│  └───────────────────────┘  │
│                              │
├─────────────────────────────┤
│  [BottomTabBar / Footer]     │
└─────────────────────────────┘
```

### 品質基準

- [ ] 全コンポーネントの配置が視覚的に分かる
- [ ] 余白（padding / gap）が表現されている
- [ ] ステップ画面は全ステップ分存在する
- [ ] DS参照コメントが主要コンポーネントに付与されている

## セクション 2: 使用コンポーネント一覧

### ルール

- デザインシステムのコンポーネントIDとセクション番号を **正確に** 参照する
- カスタムコンポーネントが必要な場合は「Custom」と明記し理由を記載
- バリアント・サイズの選択理由があれば備考に記載

### テンプレート

```markdown
### 使用コンポーネント一覧

| コンポーネント | DS参照 | 用途 |
|---|---|---|
| Button (Primary, L) | 9.1.1 | メインCTA |
| Card (Elevated) | 9.3.1 | コンテンツカード |
| TextField (Outlined) | 9.2.1 | テキスト入力 |
| Skeleton (card) | 9.4.3 | ローディング表示 |
```

## セクション 3: インタラクション仕様

### ルール

- **ユーザーアクション → システム応答** の形式で記述
- アニメーション・トランジション種別を明記（DS モーショントークン参照）
- 遷移先の画面名を明記

### テンプレート

```markdown
### インタラクション仕様

| # | ユーザーアクション | システム応答 | 遷移 |
|---|---|---|---|
| 1 | [ボタン]をタップ | [応答の詳細] | → Screen X |
| 2 | [カード]をスワイプ | [アニメーション + 結果] | — |
| 3 | [フォーム]を送信 | バリデーション → API呼び出し → 成功Toast | → Screen Y |
```

## セクション 4: 空の状態（Empty State）

### ルール

- **ボイスマトリクス参照**: 該当文脈（オンボーディング / 空の状態 / 日常利用）のトーンを指定
- イラスト + コピー + CTA の3要素を定義
- 「空の状態が存在しない」画面は、理由を明記した上でスキップ可

### テンプレート

```markdown
### 空の状態（Empty State）

**ボイスマトリクス文脈**: 空の状態（Warmth: 5, Formality: 2, Authority: 1, Energy: 4）

┌─────────────────────────────┐
│                              │
│      [イラスト / アイコン]     │
│                              │
│   「[共感的なメッセージ]」      │
│   [補足テキスト]               │
│                              │
│   ┌───────────────────────┐  │
│   │ [CTA: 最初のアクション]  │  │
│   └───────────────────────┘  │
│                              │
└─────────────────────────────┘
```

### 品質基準

- [ ] コピーがボイスマトリクスのトーンに合致している
- [ ] CTAが明確で、ユーザーが次に何をすべきか分かる
- [ ] 禁止語リストに抵触していない

## セクション 5: エラー状態（Error State）

### ルール

- **3種のエラー** を区別: ネットワーク / サーバー / バリデーション
- **ボイスマトリクス文脈**: エラー / 問題のトーンを使用
- リカバリーアクション（再試行 / 代替手段）を必ず提示

### テンプレート

```markdown
### エラー状態（Error State）

**ボイスマトリクス文脈**: エラー / 問題

| エラー種別 | 表示 | メッセージ | リカバリー |
|---|---|---|---|
| ネットワーク | InlineAlert (warning) | 「[メッセージ]」 | 再試行ボタン |
| サーバー (5xx) | FullScreen Error | 「[メッセージ]」 | しばらく待って再試行 |
| バリデーション | Field Error (inline) | 「[メッセージ]」 | フィールドハイライト + ガイド |
```

## セクション 6: ローディング状態（Loading State）

### ルール

- **Skeleton優先**: コンテンツの形状が予測可能な場合はSkeleton
- **Spinner**: 形状が不明な場合のフォールバック
- **Progressive**: 段階的に表示可能なコンテンツ（リスト等）
- **表示遅延しきい値**: 300ms未満は非表示 / 300ms-1sはSpinner / 1s以上はSkeleton

### テンプレート

```markdown
### ローディング状態（Loading State）

**初期表示（データフェッチ中）**:

┌─────────────────────────────┐
│  [Header: 即座に表示]         │
├─────────────────────────────┤
│  ┌───────────────────────┐  │
│  │ ████████████ ← Skeleton │  │
│  │ ██████████            │  │
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │ ████████████          │  │
│  │ ██████████            │  │
│  └───────────────────────┘  │
└─────────────────────────────┘

| 要素 | 方式 | 遅延 | アニメーション |
|---|---|---|---|
| Header | 即座表示 | 0ms | — |
| メインカード | Skeleton | 300ms | shimmer (1.5s loop) |
| サブコンテンツ | Progressive | 0ms | fadeIn (300ms) |
```

## セクション 7: デザイナーズノート

### ルール

- **設計判断の根拠**: なぜこの構造 / レイアウト / 配置にしたか
- **トレードオフ**: 何を犠牲にして何を優先したか
- **将来の改善**: 現時点での制約と将来的な拡張ポイント

### テンプレート

```markdown
### デザイナーズノート

> **判断**: [主要な設計判断を1文で]
>
> [根拠の説明: 2-3文]
>
> **トレードオフ**: [何を犠牲にしたか] → [何を得たか]
>
> **将来**: [Phase 2以降での改善ポイント]
```

## 特殊画面のガイド

### オンボーディング（ステップ型画面）

- 全ステップのワイヤーフレームを作成
- ステップ間の遷移ルール（戻る/スキップ可否）を明記
- プログレスインジケータの表示ルール

### チャット / メッセージング画面

- メッセージバブルのレイアウト（自分 / 相手 / システム）
- 入力中インジケータ
- メッセージ送信 → 応答待ち → 応答表示のフロー
- Immersive Mode のナビゲーション最小化ルール

### ダッシュボード画面

- カード配置の優先順位（上 → 下、左 → 右）
- データ更新頻度とリアルタイム性の要件
- ウィジェット間の依存関係

### フォーム画面

- バリデーションタイミング（onBlur / onSubmit / realtime）
- 長いフォームの分割戦略（ステッパー / アコーディオン）
- 入力補助（オートコンプリート / マスク / ヒント）
