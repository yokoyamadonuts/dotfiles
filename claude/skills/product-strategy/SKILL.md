# プロダクト戦略策定スキル

## 概要

AIを思考パートナーとして活用し、Rumelt's Strategy Kernel フレームワークに基づいてプロダクト戦略を策定する。戦略とは「どこで戦い、どう勝つか」を決める厳しいトレードオフの意思決定であり、単なる機能リストや目標リストではない。

## フレームワーク

### Rumelt's Strategy Kernel

戦略の核心は3つの要素：

1. **DIAGNOSIS（診断）**: 何が本当に起きているのか？
   - 核心的な課題・機会を特定する
   - 複雑さを切り捨てて本質的な問題を名指しする
   - データと競合状況に基づく

2. **GUIDING POLICY（基本方針）**: アプローチは何か？
   - どこで戦うかの厳しい選択
   - 一部の機会にNOと言うことで焦点を作る
   - トレードオフを通じて優位性を生み出す

3. **COHERENT ACTIONS（整合的アクション）**: どう実行するか？
   - 互いに強化し合う具体的な施策
   - 依存関係を考慮したシーケンスされたロードマップ
   - 戦略に集中したリソース配分

### Gibson Biddle DHM モデル（補助フレームワーク）

各戦略的施策を3軸で評価：
- **Delight（魅力）**: ユーザーを本当に喜ばせるか？
- **Hard to copy（模倣困難）**: 競合が簡単にコピーできないか？
- **Margin-enhancing（収益向上）**: ビジネスモデルを改善するか？

## コアワークフロー

### ステップ1: コンテキスト把握

現状を把握する：
- プロジェクト・プロダクトの背景ドキュメントを読む
- チーム構成、リソース制約、過去の成果を確認
- 既存の戦略や方針文書があれば読む

### ステップ2: 競合リサーチ（並列エージェント）

```javascript
// 3-5の競合を並列でリサーチ
Task({
  description: "Research competitor A",
  prompt: "競合AのAI/主要機能、ポジショニング、価格、ターゲット市場を調査せよ...",
  subagent_type: "general-purpose"
})
// + 他の競合
```

各エージェントが調査する内容：
- どんな機能をリリースしているか
- AI/主要技術のポジショニングと価格
- 何がうまくいっていて何がうまくいっていないか
- ホワイトスペース（競合がカバーしていない領域）

### ステップ3: DIAGNOSIS（診断）の策定

競合リサーチとコンテキストに基づいて、戦略的状況の診断を策定する。

AskUserQuestionツールで選択式の戦略的質問を3〜5問行う：

例：
```javascript
AskUserQuestion({
  questions: [
    {
      question: "主なターゲットセグメントはどれですか？",
      header: "ターゲット",
      options: [
        { label: "SMB（小規模チーム）", description: "5-20人のチーム、セルフサーブ型" },
        { label: "ミッドマーケット", description: "50-500人の組織、営業主導" },
        { label: "エンタープライズ", description: "500人以上、複雑な組織構造" },
        { label: "個人開発者", description: "フリーランスや個人プロジェクト" }
      ],
      multiSelect: false
    },
    {
      question: "主なディストリビューション戦略は？",
      header: "配信",
      options: [
        { label: "Build in Public", description: "SNSでの開発過程公開（Pieter Levels方式）" },
        { label: "Free Tool Funnel", description: "無料ツールで集客→有料版にアップセル（Marc Lou方式）" },
        { label: "Content Marketing", description: "ブログ・SEOでの長期的な流入" },
        { label: "既存チャネル", description: "既に持っているオーディエンスを活用" }
      ],
      multiSelect: false
    }
  ]
})
```

### ステップ4: GUIDING POLICY（基本方針）の策定

診断に基づいて、3つの戦略的方向性の選択肢を提示する。各選択肢にはトレードオフを明示する。

**悪い基本方針の例（避けるべき）：**
- 「収益を増加させる」→ 目標であって戦略ではない
- 「ユーザーを喜ばせる」→ 選択がない
- 「市場リーダーになる」→ HOWもWHEREもない

**良い基本方針の例：**
- 「SMBに特化し、エンタープライズ機能は捨てる。ワークフロー統合の深さで差別化する」

### ステップ5: COHERENT ACTIONS（整合的アクション）の策定

選択された方針に基づいて、互いに強化し合うアクションプランを策定する。各アクションをDHMモデルで評価する。

### ステップ5.5: インディー開発者向け戦略パターン

ソロ開発者・小規模チームの場合、以下の検証済みパターンを検討する：

#### Build in Public（Pieter Levels方式）
- 開発プロセスを公開してオーディエンスを構築
- DHM評価: **D[高]**（コミュニティとの直接的なつながり）/ **H[高]**（個人のブランドは模倣困難）/ **M[中]**（直接収益には寄与しないが認知度向上）

#### Output Goals > Outcome Goals（Marc Lou方式）
- 「MRR $10K」ではなく「毎週1機能リリース」にフォーカス
- コントロールできるアウトプットを目標にする
- DHM評価: **D[中]**/ **H[低]**（概念自体はコピー可）/ **M[高]**（継続的なリリースが収益を改善）

#### PMFサイクル4ステージ（Tibo方式）
- **検証中** → **成長中** → **安定** → **Kill** のサイクルでポートフォリオ管理
- 3ヶ月収益ゼロのプロダクトはKill or Pivot
- 勝者に集中し、敗者を素早く切る

#### BYOKモデル（Tony Dinh方式）
- AI機能を持つプロダクトでユーザーが自分のAPIキーを持ち込む
- DHM評価: **D[中]**（APIキー管理のUXは劣る）/ **H[中]**（モデル自体は模倣可）/ **M[高]**（インフラコストゼロ、利益率最大化）
- 判断基準: AI APIコストがMRRの20%を超えるならBYOK検討

### ステップ6: Devil's Advocate（反論検証）

策定した戦略をストレステストする：

```javascript
Task({
  description: "Devils advocate review",
  prompt: "この戦略を攻撃的に批判せよ。以下を検証：
  1. 仮定の検証: 間違っている可能性のある仮定は？
  2. 競合の対応: 競合がこれをコピーできない理由は？
  3. 顧客の関心: 顧客が本当にこれを気にするか？
  4. 実行可能性: リソースで本当に実行可能か？
  5. 機会コスト: やらないことの価値は？",
  subagent_type: "general-purpose"
})
```

### ステップ7: Pre-mortem（事前検死）

「12ヶ月後にこの戦略が完全に失敗した。なぜか？」を想像して書き出す。

### ステップ8: 戦略ドキュメント出力

```markdown
# [プロダクト名] 戦略ドキュメント

生成日: [日付]

## エグゼクティブサマリー
[3つの箇条書きで要約]

## DIAGNOSIS（診断）
### 戦略的状況
[市場環境、競合状況、自社の立ち位置]

### 核心的な課題/機会
[一文で核心を突く]

## GUIDING POLICY（基本方針）
### 我々のアプローチ
[明確な選択とトレードオフ]

### やらないこと（明示的なNo）
[捨てる領域を列挙]

## COHERENT ACTIONS（整合的アクション）
### Q1: [施策名]
- DHM評価: D[高/中/低] H[高/中/低] M[高/中/低]
- 依存関係: [前提条件]

### Q2: [施策名]
...

## 競合分析サマリー
[キーインサイト]

## リスクと軽減策
[Devil's Advocate と Pre-mortem の結果]

## 成功指標
[KPI と目標値]
```

## 出力ファイル

- `docs/strategy-[name].md` - 戦略ドキュメント
- `docs/strategy-[name]-competitive.md` - 競合分析（任意）
