# テラスタル論（SV環境: レギュレーションA〜I）

対戦中1回だけポケモンのタイプを変更できるギミック。構築・選出・立ち回りの全段階に影響する。

## テラスタルの3分類

| 使い方 | 説明 | 優先度 |
|-------|------|-------|
| **能動的テラス** | こちらから切って勝ち筋を太くする（一致火力UP等） | **最優先** |
| **防御的テラス** | 弱点技を半減以下にして耐える | 状況次第 |
| **強要されるテラス** | 不利な場面を切り返すために仕方なく切る | **避けるべき** |

> 「テラスを強要される弱い使い方を拒否する。こちらの都合で太い勝ち筋となるテラスタルを切る」（ぼのぼに S15最終1位）

## テラスタル判断の基準

- **切るべき場面**: テラスによって確定数が変わり、そのまま試合が決まる場面
- **切らないべき場面**: テラスを切っても状況が好転しない / 後で必要になる可能性がある
- **構築段階の設計**: テラスなしでも最低限動ける構築にし、テラスは「勝ちを確実にする」ためだけに使う
- **テラス先の競合を避ける**: 構築内でテラスを切りたいポケモンが2体以上いると選出が歪む

## 構築における設計

出力テンプレートに以下を含める:

```markdown
## テラスタル設計
- メインテラス先: [ポケモン] → [テラスタイプ]（能動的: [理由]）
- サブテラス先: [ポケモン] → [テラスタイプ]（防御的: [条件]）
- テラス権競合: [なし / あり（どう解決するか）]
```

## 選出への影響

- 処理手段が「テラスタル頼み」の時点で選出が破綻している
- テラスなしで勝てる選出を基本とし、テラスは保険or決定打
- 相手のテラスタイプは不明 → 安定択を優先

## アンチパターン

| 失敗 | 回答 |
|------|------|
| テラスを強要される構築 | テラスなしで動ける設計＋能動的テラスで勝ち筋を太くする |
| 全員にテラス切りたい | テラス権競合 → テラスなしで動ける軸を中心にする |
| 初手テラス前提 | テラス読みで崩される → 初手テラスなしで動ける選出を優先 |
