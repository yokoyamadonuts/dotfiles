# メタカバレッジ戦略スキル

## 概要

競争環境における支配的要素（トップN脅威）を特定し、最小のリソースで全対応する戦略を構築するフレームワーク。ポケモン競技の歴代最多最終1位プレイヤー・くろこ氏の構築理論を抽象化した方法論。

**核心思想**: 「トップNに勝てないと安定しない。ならば、トップN全てに動ける単一のレバーを見つけろ」

## 適用領域

| 領域 | 支配的要素の例 | 戦略の例 |
|------|-------------|---------|
| プロダクト開発 | 競合の主力機能3-5個 | 全機能に対抗できる単一アーキテクチャ |
| 技術選定 | 主要ユースケース3-5個 | 全ユースケースをカバーするスタック |
| 営業戦略 | 顧客の主要懸念3-5個 | 全懸念に回答できるピッチ |
| セキュリティ | 主要脅威ベクトル3-5個 | 全脅威を緩和する単一防御層 |
| API設計 | 主要クライアントパターン3-5個 | 全パターンを満たすインターフェース |

## 5つの原則（くろこ理論の抽象化）

### 原則1: 環境のトップN特定

支配的要素を正確に見極める。「何に勝てないとダメか」を先に定義する。

> 「レギュHのトップ4はガチグマ、カイリュー、サーフゴー、ブリジュラス。この4体に勝てないとまず安定しない」

### 原則2: 単一レバーの発見

トップN全てに動ける単一の手段を探す。1つのリソースで複数の支配的要素に対応できる「万能キー」の発見が構築の核。

> 「ラグラージが全部に行けるくねと。あくび＋食いしばり＋ステロ＋守るで全対応できる」

### 原則3: テンプレートからのずらし

全員が知っている定番の回答ではなく、環境から少しずらした非標準の手段を採用する。情報が高速に共有される環境では、テンプレートは対策される。

> 「全部の型が違う。環境からずらすのが大事。テンプレはみんな見た瞬間に対処できるから」

### 原則4: 破壊分担（どちらか絶対通る理論）

単一レバーだけでは崩せない領域に対し、相互補完する2つの手段を用意する。どちらか一方が必ず通る構造にする。

> 「ガブとガチグマを絡めることによって絶対どっちか通る」

### 原則5: 理論先行の構築

「なんとなく強そう」ではなく、トップNへの対応表を理論的に埋めてから構築する。組んだ瞬間に勝てると確信できる状態を目指す。

> 「組んだ瞬間に勝てるなって思った。全部の理論が噛み合っている」

## コアワークフロー

### ステップ1: 環境診断 — 支配的要素の特定

競争環境を分析し、「勝てないと話にならない」トップN要素を特定する。

```javascript
AskUserQuestion({
  questions: [{
    question: "分析対象の競争環境は何ですか？",
    header: "環境種別",
    options: [
      { label: "プロダクト市場", description: "競合プロダクトの主力機能への対策" },
      { label: "技術選定", description: "主要ユースケースへの対応" },
      { label: "セキュリティ", description: "主要脅威ベクトルへの対策" }
    ],
    multiSelect: false
  }]
})
```

支配的要素の特定基準:
1. **出現頻度**: 環境内で最も頻繁に遭遇するもの（使用率トップ）
2. **影響度**: 対策しないと致命的になるもの
3. **相互関係**: 組み合わせで出現するパターン

目標: **3〜5個**の支配的要素をリスト化する。

### ステップ2: 単一レバーの探索

トップN全てに対応可能な単一のリソース・手段・アーキテクチャを探す。

**探索手法**:

1. **対応マトリクスの作成**: 行=候補手段、列=トップN要素、セル=対応可否
2. **既存事例の研究**: 過去にトップを取った人はどうやって各要素に勝ったか（記事・事例研究）
3. **交差点の発見**: 各要素の弱点が重なるポイントを探す

```markdown
## 対応マトリクス

| 候補手段 | 脅威A | 脅威B | 脅威C | 脅威D | カバー率 |
|---------|-------|-------|-------|-------|---------|
| 手段X   | ?     | ?     | ?     | ?     | ?/4     |
| 手段Y   | ?     | ?     | ?     | ?     | ?/4     |
| 手段Z   | ?     | ?     | ?     | ?     | ?/4     |
```

**判定基準**: カバー率が75%以上（3/4以上）の手段を単一レバー候補とする。

### ステップ3: ずらし設計 — 非標準化

発見したレバーを環境のテンプレートからずらす。

**ずらしの3パターン**:

| パターン | 説明 | 例 |
|---------|------|-----|
| パラメータずらし | 同じ手段の設定値を変える | 速度特化型にする（相手の想定を超える） |
| 機能ずらし | 標準装備を非標準のものに入れ替える | 守るの採用（誰も入れない技で対応範囲拡大） |
| タイミングずらし | 環境が注目する前に採用する | まだ誰も評価していない手段を先取り |

### ステップ4: 補完構造の設計

単一レバーだけではカバーできない領域に対して、補完手段を設計する。

**補完設計の原則**:

1. **破壊分担**: 2つの手段で「どちらか必ず通る」構造を作る
2. **役割明確化**: 各手段の担当範囲を明示し、オーバーラップを減らす
3. **最悪ケースの想定**: 単一レバーが機能しなかった場合のフォールバック

```markdown
## 補完構造

### 単一レバー: [手段名]
- 対応範囲: 脅威A, B, C, D
- 対応できないケース: [具体的な条件]

### 補完手段1: [手段名]
- 担当: 単一レバーが対応できないケースX
- トレードオフ: [何を犠牲にしているか]

### 補完手段2: [手段名]
- 担当: 単一レバーが対応できないケースY
- 破壊分担: 補完手段1が通らない時、こちらが通る
```

### ステップ5: 理論検証 — 対応表の完成

全ての支配的要素に対する対応が理論的に埋まっていることを検証する。

**検証チェックリスト**:

- [ ] トップN全てに対する対応手段が明記されている
- [ ] 各対応が「なぜ機能するか」の理由が説明できる
- [ ] 単一レバーが機能しない条件が洗い出されている
- [ ] その条件に対する補完手段が存在する
- [ ] 「どちらか必ず通る」構造が成立している
- [ ] テンプレートからのずらしが少なくとも1つ含まれている

**フィードバックループ**: チェックリストで穴が見つかった場合、ステップ2（単一レバー探索）またはステップ4（補完構造設計）に戻って修正する。「組んだ瞬間に勝てると思える」状態になるまで繰り返す。

## 出力ファイル

- `docs/meta-coverage-[topic].md` - 戦略設計書

## アンチパターン

| アンチパターン | 問題 | くろこ理論での対応 |
|-------------|------|-----------------|
| 全方位対応 | リソースが分散し何にも勝てない | トップNに絞って集中カバー |
| テンプレコピー | 相手に対策済み | ずらしで想定を崩す |
| 感覚的構築 | 穴に気づかず崩壊する | 対応表で理論的に検証 |
| 単一手段依存 | 対策されたら詰む | 破壊分担で必ず1つ通す |
| 過剰な保険 | 攻め手がなくなる | 役割を明確化し最小構成で守る |
