# Brand Identity Builder

Pentagramのクリエイティブディレクターとして、公開可能な包括的ブランドアイデンティティブックを構築する。

## 前提条件

以下のいずれかが既に存在すること:
- デザインシステム（カラー、タイポグラフィ等の定義）
- 戦略書 / PRD（ターゲット、ポジショニング、差別化）
- プロダクト仕様（機能、UX設計）

**ゼロからの場合**: まず `building-design-system` スキルでデザインシステムを構築し、戦略的方向性を固めてから本スキルを実行する。

## Process

### Phase 1: コンテキスト収集

以下を並列で調査する:

1. **既存デザイン資産**: デザインシステム（カラーパレット、タイポグラフィ、コンポーネント定義）を読み込む
2. **プロダクト思想**: README、CLAUDE.md、戦略書、PRDから核心思想・ターゲット・差別化ポイントを抽出
3. **競合環境**: 戦略書から差別化マトリクスを確認。ない場合は市場ポジションを整理
4. **既存ブランド資産**: ロゴ、ブランドガイドライン、マーケティング素材があれば確認

**重要**: 既存のデザインシステムのカラー・フォント定義をブランドカラーに昇格させる形で構築する。矛盾させない。

### Phase 2: ブランド基盤の策定

ユーザーに提示して承認を得る:

1. **ブランドアーキタイプ**: 12のユング的アーキタイプから1-2を選定し配合比を決定
2. **ブランドパーソナリティ**: 5つの性格特性（各特性に「何であるか」「何でないか」を定義）
3. **タグライン候補**: 3案提示

→ ユーザー承認後、Phase 3へ

### Phase 3: ブランドブック構築

プロジェクトの `docs/` ディレクトリに `brand-identity.md` を出力する。

#### 必須20ページ構成

```
Page 1:  表紙（ロゴ + タグライン）
Page 2:  ブランドストーリー（思想的起源、存在意義、ブランドの約束）
Page 3:  ブランドアーキタイプ（選定理由、却下理由、配合比）
Page 4:  ブランドパーソナリティ（5特性 + パーソナリティスペクトラム図）
Page 5:  ボイスマトリクス（4軸定義 + 6文脈別ガイド + 禁止語リスト）
Page 6:  メッセージ階層（タグライン → ピッチ → 100字 → ナラティブ → ワンライナー集）
Page 7-8: ロゴ3方向提案（A: 活字型 B: シンボル型 C: 融合型 + 選定理由）
Page 9:  ロゴバリエーション（フル / コンパクト / アイコン / モノクロ）
Page 10: ロゴ使用ルール（クリアスペース / 最小サイズ / 背景組み合わせ / 禁止例10+）
Page 11-12: カラーシステム（Hex / RGB / CMYK / Pantone近似 + 選定理由 + 使用比率）
Page 13: タイポグラフィ（ファミリー選定理由 + ペアリング図 + 階層原則）
Page 14: ビジュアルスタイル（方向性定義 + 三原則 + イラストスタイル + テクスチャ）
Page 15: グラフィック要素（ブランドモチーフ + パターン + 区切り線 + 使用ルール）
Page 16-17: ブランド展開例（App Store / SNS / 名刺 / Web — ASCII wireframe付き）
Page 18: 写真ガイドライン（ムード / 被写体ガイド / カラーグレーディング）
Page 19: 禁止事項（表現 / ビジュアル / コミュニケーション / 競合 — Do/Don't表）
Page 20: ブランドチェックリスト（8カテゴリ × 5項目 = 40項目の検証リスト）
```

#### 付録（必須）

```
- ブランド用語集（プロダクト固有の用語 + 定義 + 使用文脈）
- デザインシステムとの整合マトリクス（全ブランド要素 ↔ DS参照の対応表）
- 戦略書との一貫性チェック（全戦略的方針 ↔ ブランド対応の対応表）
```

### Phase 4: 検証

- [ ] Phase 2 後: アーキタイプ・パーソナリティ・タグラインの承認
- [ ] Phase 3 中: ロゴ3方向提案の選定確認
- [ ] Phase 3 後: 全20ページ完成時に最終レビュー

## 各ページの詳細仕様

### Page 2: ブランドストーリー

必須要素:
- **起源ナラティブ**: なぜこのプロダクトが存在するのか（感情に訴える物語形式）
- **思想的ルーツ**: インスピレーション源 → プロダクトへの翻訳（表形式）
- **ブランドの約束**: ユーザーへの1-2文のコミットメント
- **存在意義（Brand Purpose）**: 1文で凝縮

### Page 3: ブランドアーキタイプ

12のアーキタイプ:
```
Innocent, Sage, Explorer, Hero, Outlaw, Magician,
Regular Guy, Lover, Jester, Caregiver, Creator, Ruler
```

必須要素:
- 選定したアーキタイプ（1-2個）の特性とプロダクトでの表現（表形式）
- 却下したアーキタイプ3+の却下理由（表形式）
- 配合比の図（バー表示）

### Page 5: ボイスマトリクス

4軸定義:
```
1. Warmth（温度）: 冷淡 ←→ 温かい
2. Formality（形式）: カジュアル ←→ フォーマル
3. Authority（権威）: 対等 ←→ 権威的
4. Energy（エネルギー）: 静か ←→ 活発
```

6文脈別ガイド（各文脈に4軸の数値 + 例文 + NG例文）:
```
1. オンボーディング
2. 日常利用
3. 空の状態 / エンプティステート
4. 進捗・達成
5. エラー / 問題
6. 危機対応（該当する場合）
```

禁止語リスト: 禁止語 → 代替語 → 理由（表形式で10+項目）

### Page 6: メッセージ階層

5レベル:
```
Level 1: タグライン（3秒）— 1文 + バリエーション2-3 + 英語版
Level 2: エレベーターピッチ（30秒）— 3-4文
Level 3: 100字コピー — App Store / SNS bio向け
Level 4: ブランドナラティブ（2分）— 6-8段落の物語
Level 5: ワンライナー集 — 用途別（App Store / SNS / リリース / ターゲット別）
```

### Pages 7-8: ロゴ3方向提案

3方向:
```
A: 活字型 — テキストベースのロゴタイプ
B: シンボル型 — アイコン/シンボル重視
C: 融合型 — テキストとシンボルの組み合わせ
```

各方向に:
- ASCII表現のロゴ図
- コンセプト説明（1段落）
- フォント・色・サイズの仕様
- 長所・短所（各2-3項目）

最後に推奨案を選定し、選定理由を3つ以上列挙。

### Pages 11-12: カラーシステム

既存デザインシステムのカラーを昇格させる。各色に:
```
- Hex / RGB / CMYK / Pantone近似値
- 役割（1文）
- 使用比率（%）
- 選定理由（1段落 — なぜこの色なのか、何を表現するのか）
```

カラー使用比率のバーチャートを含める。

### Page 20: ブランドチェックリスト

8カテゴリ:
```
1. ロゴ & アイデンティティ（5項目）
2. カラー（6項目）
3. タイポグラフィ（5項目）
4. ボイス & トーン（5項目）
5. ビジュアル（5項目）
6. プレッシャーチェック（該当する場合、5項目）
7. 倫理チェック（該当する場合、5項目）
8. 技術チェック（5項目）
```

各項目はMarkdownチェックボックス `- [ ]` 形式。

## 品質チェックリスト

- [ ] 全20ページ + 付録が含まれている
- [ ] デザインシステムの全カラー・フォントがブランドカラー・フォントとして対応している
- [ ] 戦略書の全方針がブランド要素に反映されている
- [ ] ロゴ3方向すべてにASCII図・長所・短所がある
- [ ] ボイスマトリクスに6文脈 × 4軸の数値がある
- [ ] メッセージ階層が5レベル揃っている
- [ ] 禁止語リストが10項目以上
- [ ] ブランドチェックリストが40項目以上
- [ ] 付録の整合マトリクスがデザインシステムの全要素をカバーしている

## 重要原則

1. **デザインシステムとの整合**: 既存DSのトークンをブランド要素に昇格させる。新しい色やフォントを勝手に追加しない
2. **戦略との一貫性**: 戦略書の方針がブランド表現に翻訳されていることを付録で検証する
3. **実用性**: すべてのガイドラインが具体的で、制作者が迷わず判断できる粒度
4. **文化的配慮**: ターゲット市場の文化・言語に適した表現（日英バイリンガル対応等）
5. **拡張性**: 将来の市場拡大（Phase 1→3）に対応できる柔軟なブランド構造
