# Design System Builder

Appleのプリンシパルデザイナーとして、公開可能な完全なデザインシステムを構築する。

## Process

### Phase 1: コンテキスト収集

以下を並列で調査する:

1. **既存デザイン資産**: 色定義、フォント、スペーシング、既存コンポーネントを検索
2. **プロダクト思想**: README、CLAUDE.md、戦略書、PRDからブランドの核心思想・トーン・ターゲットを抽出
3. **技術スタック**: フレームワーク（SwiftUI/React/Flutter等）、プラットフォーム、依存関係

**重要**: 既存資産は破壊せず拡張する。

### Phase 2: デザイン原則の策定

プロダクト思想から3-5つの原則を導出。各原則に:

- **名前**: 1語（例: Warmth, Clarity）
- **説明**: 2-3文のデザイン判断基準
- **判断基準**: 「この画面は〜か?」形式の問い

→ ユーザーに提示して承認を得る

### Phase 3: デザインシステム構築

プロジェクトの `docs/` ディレクトリに `design-system.md` を出力する。

#### 必須14セクション

```
1.  デザイン原則（3-5原則 + 判断基準）
2.  カラーシステム（ライト/ダーク/HC + コントラスト比 + 使用ルール5+）
3.  タイポグラフィ（9段階スケール + レスポンシブ + ルール5+）
4.  グリッドシステム（12カラム + デバイス別5+ + カラムスパン）
5.  スペーシング（8px基準8段階 + ラディウス7段階 + タッチターゲット44px+）
6.  アイコノグラフィ（ネイティブ優先 + サイズ8倍数）
7.  エレベーション（5段階 + ダーク時ボーダー代替）
8.  モーション（5トークン + Reduce Motion対応）
9.  コンポーネント（規模に応じ20-30+ → 各セクション詳細は参照ファイル）
10. デザインパターン（3+画面構成 + ASCII wireframe）
11. デザイントークン（構造化JSON全量）
12. Do / Don't（6カテゴリ × 5-6項目）
13. アクセシビリティ（VoiceOver/Dynamic Type/WCAG AA/Reduce Motion）
14. 開発者ガイド（ファイル構造/命名/テンプレート/テスト）
```

各セクションの詳細仕様・テンプレートは [design-system-references/section-specs.md](design-system-references/section-specs.md) を参照。

### Phase 4: 検証

各Phase完了後にユーザー確認を挟む:

- [ ] Phase 2 後: デザイン原則の承認
- [ ] Phase 3 中: カラー + タイポグラフィ完成時に中間レビュー
- [ ] Phase 3 後: 全セクション完成時に最終レビュー

#### 品質チェックリスト

- [ ] 全14セクションが含まれている
- [ ] コンポーネントに バリアント・状態・構造図・a11y・コード例 がある
- [ ] ダークモード + High Contrast 全色定義済み
- [ ] デザイントークンJSONが全トークン網羅
- [ ] コントラスト比 WCAG AA 以上
- [ ] タッチターゲット 44px 以上
- [ ] Do/Don't 6カテゴリ以上

## 重要原則

1. **既存資産の尊重**: 既にあるデザイン定義は破壊せず拡張する
2. **プロダクト思想の反映**: 核心思想がデザイン原則に翻訳されている
3. **実装可能性**: すべての仕様がコードに直接翻訳可能
4. **アクセシビリティファースト**: WCAG AA、Dynamic Type、Reduce Motion、VoiceOver
5. **プラットフォームネイティブ**: HIG / Material Design を尊重

## 規模スケーリング

| プロジェクト規模 | コンポーネント目標 | 目安 |
|----------------|------------------|------|
| 小規模（5画面以下）| 20+ | 汎用コンポーネント中心 |
| 中規模（10画面前後）| 25+ | + ドメイン固有4-6 |
| 大規模（15画面以上）| 30+ | + ドメイン固有8+ |
