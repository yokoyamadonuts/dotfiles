# データ分析スキル

## 概要

CSV・JSON等のデータファイルを読み込み、構造化された分析ワークフローで意思決定に必要なインサイトを抽出する。プロダクトのファネル分析からA/Bテスト分析まで対応する。

## 分析ワークフロー

### Phase 1: Discovery（発見）

データからパターンと問題を発見する。

#### ステップ1: データの理解

```python
# データファイルを読み込んで構造を把握
# - カラム名とデータ型
# - レコード数
# - 欠損値の有無
# - 基本統計量（平均、中央値、標準偏差）
```

#### ステップ2: ファネル分析（該当する場合）

```markdown
| ステップ | 流入ユーザー数 | 完了ユーザー数 | 完了率 | 中央値時間 |
|---------|-------------|-------------|--------|---------|
| Step 1  | 10,000      | 10,000      | 100%   | 0 min   |
| Step 2  | 10,000      | 7,200       | 72%    | 18 min  |
| Step 3  | 7,200       | 2,880       | 40%    | 45 min  |
```

**最大のドロップオフポイントを特定する**

#### ステップ3: セグメント分析

データを意味のあるセグメントに分割して分析する：
- ユーザー属性別（プラン、会社規模、地域等）
- 行動パターン別（ヘビーユーザー vs ライトユーザー）
- 時期別（月次、週次、日次トレンド）

#### ステップ4: 原因仮説の構築

データのパターンから「なぜ？」の仮説を構築する。ユーザーに仮説を提示し、議論する。

### Phase 2: Impact Estimation（インパクト推定）

施策の効果を事前に推定する。

#### ステップ1: ベースラインの確立

```markdown
## 現状のKPI
- 対象指標: [例: アクティベーション率]
- 現在値: [例: 45%]
- データポイント数: [例: 10,000ユーザー/月]
```

#### ステップ2: シナリオ分析

3つのシナリオで推定する：

```markdown
| シナリオ | 改善率 | 新しい値 | 年間影響額 | 根拠 |
|---------|--------|---------|----------|------|
| 保守的   | +5%   | 50%     | $XXX     | [類似事例・ベンチマーク] |
| 基本     | +10%  | 55%     | $XXX     | [内部データ・トレンド] |
| 楽観的   | +20%  | 65%     | $XXX     | [最良ケースの仮定] |
```

#### ステップ3: 開発コストとの比較

```markdown
## ROI分析
- 開発コスト: [エンジニア人月 × 単価]
- 回収期間（保守的）: [月数]
- 回収期間（基本）: [月数]
- 推奨判断: [投資すべき / 保留 / 却下]
```

### Phase 3: Experiment Analysis（実験分析）

A/Bテスト等の実験結果を分析する。

#### ステップ1: トップライン結果

```markdown
## 実験結果サマリー

| 指標 | コントロール | テスト | 変化 | 統計的有意性 |
|------|-----------|-------|------|------------|
| 主要KPI | X% | Y% | +Z% | p < 0.05 ✓ |
```

#### ステップ2: セグメント別分析

**トップラインが失敗に見えても、セグメントで成功している可能性がある。**

```markdown
## セグメント別結果

| セグメント | コントロール | テスト | 変化 | 有意性 |
|----------|-----------|-------|------|--------|
| 小規模チーム | X% | Y% | +Z% | ✓ |
| 大規模チーム | X% | Y% | -Z% | ✓ |
```

#### ステップ3: 品質指標の確認

主要KPIが改善されても、品質指標が劣化していないか確認する：
- リテンション率（短期・長期）
- エンゲージメント深度
- ユーザー満足度
- エラー率・サポートチケット数

#### ステップ4: 意思決定フレームワーク

```markdown
## 判断マトリクス

| 条件 | 判断 |
|------|------|
| 全セグメントで改善、品質指標OK | ✅ 全面ロールアウト |
| 一部セグメントで改善、品質OK | ⚠️ ターゲットロールアウト |
| KPI改善だが品質劣化 | ⚠️ イテレーションして再実験 |
| KPI改善なし | ❌ 中止または再設計 |
```

### Phase 4: Indie Revenue Analysis（インディー収益分析）

インディー開発者向けの収益・成長指標分析。

#### バニティメトリクス vs リアルメトリクス

**バニティメトリクスに騙されない**。以下の対比を常に意識する：

| バニティメトリクス（危険） | リアルメトリクス（信頼） |
|-------------------------|----------------------|
| 総ユーザー数 | 有料ユーザー数 |
| ページビュー | コンバージョン率 |
| SNSフォロワー数 | プロダクトへの流入数 |
| サインアップ数 | アクティベーション率 |
| 「気に入った」の声 | 実際の支払い |
| ダウンロード数 | DAU/MAU比率 |

#### インディーダッシュボードテンプレート

```markdown
## [プロダクト名] 月次ダッシュボード

### 収益
- MRR: $[金額] ([前月比]%)
- ARR: $[金額]
- 新規有料: [数]
- チャーン: [数] ([率]%)
- ARPU: $[金額]

### 成長
- 有料ユーザー数: [数]
- 無料→有料 転換率: [%]
- 自然流入率: [%]（広告なしでの獲得）

### 効率
- 開発時間: [時間/週]
- サポート時間: [時間/週]
- インフラコスト: $[金額]
- 利益率: [%]
```

#### Kill or Keep 判定基準（Tibo方式）

プロダクトを継続するか撤退するかの判断：

| 条件 | 判定 | アクション |
|------|------|-----------|
| 3ヶ月経過 + MRR $0 | **Kill** | 撤退。学びを記録して次へ |
| 3ヶ月経過 + MRR < $100 + 成長なし | **Kill or Pivot** | ターゲット/メッセージングを変えて再挑戦 |
| MRR $100+ + 月次成長10%+ | **Keep & Invest** | マーケティング強化、機能追加 |
| MRR $500+ + 成長鈍化 | **Keep & Optimize** | チャーン削減、ARPU向上に集中 |
| MRR $1000+ + 安定 | **Cash Cow** | 低保守モード。次のプロダクトへ |

**重要**: サンクコストに囚われない。3ヶ月作ったプロダクトでも、収益がなければKillする勇気を持つ。

## データ形式サポート

- **CSV**: カンマ区切りデータ（最も一般的）
- **JSON**: API レスポンスデータ
- **TSV**: タブ区切りデータ
- **Markdown テーブル**: ドキュメント内のデータ

## 出力

分析結果はユーザーとの対話中に提示する。必要に応じて以下のファイルを出力：

- `docs/analysis-[topic].md` - 分析レポート
- `docs/analysis-[topic]-recommendation.md` - 推奨事項
